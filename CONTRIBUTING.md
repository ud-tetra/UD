# Multiuser contributions

Use branch `contrib/<login>/<date>-<topic>-<unique-id>` and a unique capture directory. Add immutable files and an independent event entry. Every MANIFEST.json identifies hashes, source versions and claim status. Submit a PR and obtain review from someone other than the constructor for any bridge promotion.

An artifact correction is a new capture referencing the prior version in `supersedes`; the prior bytes stay available. A shared index is derived navigation only. Parallel contributors never claim the same capture directory and never edit one shared append-only log. New capture paths must not exist at the current main head.

Run the integrity workflow. If main advanced, update your branch and repeat the checks; never resolve a conflict by discarding another contribution. Administrative configuration changes require review and an event explaining them.

The repository currently contains a historical import, not a new scientific approval. Statements and audits inside snapshots retain their original scope and may have later amendments. Consult source versions and accepted governance before reuse.


For observables, consult `docs/UD_PREDICTIVE_DISCOVERY_PROTOCOL_v1.0.md`; PRs must report target exposure, independent reviewer, falsifier, units/readout, tests actually run and any cross-repo impact. New process documents do not change historical captures or promote claims.


## Proof-first mathematical contributions

Before describing a contribution as research closure, state the exact theorem and proof hypotheses, then capture its immutable proof ID, theorem-quality argument, counterexamples, verification and append-only ledger receipt in proofs/. CI is supporting reproduction, not proof authority. Proof status, independent review and physical promotion are separate. Record the theorem or obstruction first, code second.
