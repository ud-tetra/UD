The attached Distinction Dynamics repository snapshot is an older reconstructed/placeholder source, not this cohort. The new cochain-contrast calculation is an authored candidate with synthetic exact cases, not an acquired endpoint sequence. The `Gap2_FINAL_Finite_Genesis.png` mentioned in earlier audits was not present in the supplied `project_sources` directory. These are bounded inventory findings, not proof that no outside dataset exists.

The requested comparison is full event/no-event timing, output frame, address/seat and full Theta endpoint on the same carrier. The older two-stage `op03_blind_intake_v01` is a narrower conditional one-pair **capacity polarity** instrument and cannot by itself score complete endpoints or event timing. A zero-index swap or frame-only change must remain visible even when capacity is unchanged. A synthetic mechanism or independently coded fixture may test plumbing only; it is not an empirical target or physical confirmation.

## Provider assignment and exact return

An independent provider should return a versioned, attributable measurement protocol or event engine that never imports, calls, or derives labels from the UD historical sign/address selector, the v0.2.1 seat guard, or its predictions. Name separate source author, endpoint author, and custodian roles, their overlap, and any access to candidate code. Commit source code, dependencies, state domain, clock/window rule, initial and boundary conditions, eligibility/exclusions, tie and simultaneous-event semantics, and measurement uncertainty before acquiring endpoint labels. A non-constructor reviewer should audit independence and pretarget computability; this packet does not claim to be that review.

Return exactly these four lanes, each immutable after sealing:

| Lane | Required content | Access before prediction |
|---|---|---|
| `producer_manifest.json` | Provider identity and version, code/protocol hashes, carrier and orientation, collection scope, clock, exclusions and receipt policy | Yes, excluding any outcome-derived fact |
| `pre_event.jsonl` and raw source archive | Every consecutive exposure window, including nulls and controls, with ordered oriented `c0,c1,c2` (and `c3` if used), raw Theta-minus, source/sink frame bases, source-complete signed edge transport or certified observed/co-moving 12D route, lineage/seat maps, integrity, viability, burdens, auditable signed `G`, frozen eligibility, prior boundary | Yes |
| `hidden_endpoints.jsonl` and raw endpoint archive | Same exact window IDs/order; measured or independently generated output frame and full three-bit Theta-plus, event instant or explicit no-event window, primitive closure/transport receipts if six-edge claims are made, uncertainty and cause receipts | Custodian only until prediction seal |
| `custody_ledger.jsonl` | Hash, actor, trusted UTC receipt, signing/attestation and dependency for each freeze, acquisition, prediction, and release action | Public metadata; never endpoint content before release |

The pair order is A=(01,23), B=(02,13), C=(03,12); source and output bases are separately labeled. The six ascending oriented edges are `(01,02,03,12,13,23)`. Rational quantities should be canonical numerator/denominator strings (or a documented exact serialization). Store raw cochains and the signed `G_p^{S±}` calculation with incidence, normalization and integration method; a proxy such as a contrast score must carry a distinct name and must not silently substitute for `G`. `s_start` and `s_end` use a declared dimensionless native parameter unless a separately calibrated physical clock is supplied.

The provider may choose the source-complete ordered six-edge transport route or an observed/co-moving 12D route. The latter requires the exact pre-event transform and certificate, not merely an arbitrary 6D projection: the signed-edge residual has the same action in both 6D blocks, vanishing cross-blocks, and an exact oriented S4 image. Freeze `F`, `A_src`, `A_ren`, their typed domains/codomains, and the computation of `L+ = Im[F A_src A_ren]` and its coordinate-seat test without looking at Theta-plus. Do not infer a coordinate seat from a hidden endpoint. Pair integrity and viability are separate fields. The full signed S4 frame and its S3 pair projection must be auditable; compute `bar(Theta)^- = P_{pi(r)} Theta^-` before comparing with Theta-plus. The affine toggle is `bar(Theta)^- XOR Theta+`; a frame-only change and a zero-index swap have distinct event tags. Only a completed Theta switch advances the previous-switch index. This avoids the documented raw-versus-aligned event-label error.

## Typed record schema (normative intake request)

`SCHEMA_v0.1.json` specifies the four record shapes. Each `window_id` must be unique and stable; `(cohort_id, sequence_index)` must be consecutive from the predeclared start to end, and both files have identical ordered IDs. A window records its complete exposure interval even if the endpoint is a null. No retrospective removal, interpolation, relabeling, or eligibility revision is allowed. An unavailable value is an explicit `{ "status":"HOLD", "reason":..., "requested_from":... }`, never zero, false, `000`, a fabricated identity matrix, or an omitted row. A hold on any required source, frame, chronology, or endpoint field blocks full-endpoint scoring of that row. A missing whole window blocks cohort completeness and first-switch denominators; preserve it as an indexed hold with the declared exposure boundary. A genuinely observed null is an independent `NO_SWITCH` target receipt with complete endpoint, not a missing file.

Mandatory field groups in each **pre-event** row: IDs and interval; orientation/bases; complete raw cochains and acquisition method; raw Theta-minus and prior completed-switch boundary; source and transport route/certificate; frozen lineage/seat maps; viability/integrity/burden; raw signed-source arithmetic; eligibility and reason set before target access; hashes of raw state and pre-event receipt. The **hidden** row has exactly the same identity/interval and separately committed output frame, Theta-plus, event flag/instant or no-event receipt, raw endpoint hash, producer artifact hash, and uncertainty. Derived event flags should be recomputed after release from aligned bits; the provider's observed event tag is separately retained for disagreement analysis.

## Seal and prediction barrier

1. **Protocol freeze:** Custodian receives code/protocol/source-domain archive, SHA-256 of each raw byte stream, exclusions, expected sequence range, clock and schemas. Record an external UTC receipt or signed commit. A local workstation clock by itself is weak chronology evidence; an earlier capture was later found about 12 hours off GitHub time.
2. **Outcome acquisition:** If endpoints already exist, hash and seal the entire ordered endpoint file and raw evidence **before** opening the prediction lane. If future, freeze the protocol now and hash the endpoint bytes as soon as acquired. Custodian publishes hash and row count only; candidate operator cannot read plaintext, filenames carrying labels, row-level statistics, or any outcome-derived exclusion.
3. **Pre-event freeze:** Publish the full ordered pre-event archive and manifest hashes and independently established eligibility. Verify source and target counts/IDs under custodian control without exposing target values. Any late correction produces a new version and fresh untouched cohort.
4. **Prediction:** Run the pinned candidate and declared no-event/constant/capacity baselines in an environment without endpoint access. Commit exact predictions for **every** frozen window, including abstentions/holds, plus code hash, configuration, domain, scoring rule and SHA-256. Obtain an external receipt whose ordering is demonstrably after target seal and before plaintext release. Do not fit thresholds, frame mappings or window choices to labels.
5. **Release and audit:** Custodian verifies all hashes and barrier times, releases complete endpoint bytes, and records release receipt. Recompute affine events in output basis; check count, null coverage, timing, address, frame and full Theta endpoint separately, with predeclared denominator and holds. An independence review and physical calibration are distinct gates; no numeric match alone gives physical promotion.

The ledger should preserve a causal order such as `protocol_frozen < target_sealed <= pre_event_frozen < predictions_sealed < target_released`. Pre-event sealing may precede target sealing for future acquisition, but both must precede prediction and release, with the source data available for prediction and labels hidden. Hashes establish byte identity; they do not establish that an asserted producer was independent. Provenance needs code review, access log and attributable custody.
