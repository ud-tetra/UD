The Problem

LLMs have LT + LC. They lack LR.

Current language models can propagate tokens (transport, LT) and return coherent meaning (closure, LC). They cannot reconstruct — verify their outputs, trace claims to evidence, or repair corrupted inference chains (reconstruction, LR).

This is not an engineering gap. It is a structural gap. The UD loop spine identifies exactly what is missing.

The gap between “sounds right” and “is right” is the gap between LC and LR.

Architecture

Three Channels + One Gate

Named after the Arabic trilateral root — three independent consonants combine with a vowel template to produce meaning. Three independent channels combine with a gate to produce verified meaning.

Diagnosis

Why Current Approaches Fail

Each current approach addresses part of the LR gap. None satisfies all five structural requirements.

Chain-of-Thought (CoT)

Forces intermediate steps. Extends LC (longer closure chains). But the chain is generated by the same process as the answer — no independent verification. No spectral gap.

UD: More Tn iterations, but chain and answer share one eigenspace.
Missing: R1 (no verification subspace), R2 (no gap)

RLHF / Constitutional AI

Trains a reward model to prefer “good” outputs. But the reward model is also LC — it judges whether output sounds right, not whether it is right. You cannot stack LC systems to get LR.

UD: Corridor rotation U(θ) in V1/2. Changes preference, not verification capacity.
Missing: R1 (no verification subspace), R4 (no projector)

Retrieval-Augmented Generation (RAG)

Augments with external documents. More raw material, but the model still cannot verify its use of retrieved content. More content without more verification = more potential for hallucination.

UD: Enriches the root (more eigenspace content) without adding a projector Pλ.
Missing: R4 (no projector), R5 (repair not cheaper than generation)

Tool Use / Code Execution

Lets the model call external verifiers. Closest to LR — a calculator IS a verification subspace for arithmetic. Code execution IS reconstruction. But domain-limited: LR for math, LC for everything else.

UD: Each tool provides R1 + R2 + R4 for its domain. No universal coverage.
Missing: R3 (no active repair for non-tool domains)

Formal Verification (Lean/Coq)

True LR for mathematical statements. Satisfies all five requirements. Limitation: only works for formally specifiable claims. Most natural language cannot be stated in Lean.

UD: Full LR but verification subspace (R1) too narrow.
Missing: Scope, not structure
Structural Requirements

R1–R5: What LR Needs

Derived from the loop spine (THM-LS3, LS6, LS7, LS10). These are structural necessities, not engineering preferences.

R1Verification subspace — A degenerate subspace where checking costs zero. All paraphrases map to one point (B = 0). Contradictions map elsewhere (B > 0). TVE: the consistency manifold.✓
R2Spectral gap — A discrete, measurable boundary between verified and unverified output. Not a soft probability — a hard classification. TVE: the pass/defer/veto gate.✓
R3Active repair — Prevents decay to trivial output (Tn → P1). Runs during generation, not post-hoc. TVE: veto feeds contradiction signal back to logits before next sample.✓
R4Projector Pλ — Isolates the verified component of any output. Maps claims to equivalence classes or rejects them. TVE: the consistency encoder IS Pλ.✓
R5Cheaper than generation — Verification must cost less than generation, else the system always prefers to generate over verify. TVE: encoder (1-3B) + tracer (1-3B) = 5-10% of generator (70B).✓

Implementation

5-Phase Training Procedure

1

Standard LLM Training

Train the generator normally on standard corpora. No modification. This is the existing model.

2

Consistency Encoder

Contrastive learning: map equivalent claims to the same manifold point, contradictions to different points.

Datasets: SNLI, MultiNLI, ANLI, QQP, PAWS, ParaNMT
3

Support Tracer

Binary classification on (claim, evidence, label) triples. Train to score claim-evidence alignment.

Datasets: FEVER, Natural Questions, WANLI, attribution benchmarks
4

Gate Training

Freeze all three channels. Train gate on (output, consistency, support) → quality. Learn optimal pass/defer/veto thresholds.

Objective: maximize verified correct, penalize hallucination
5

Repair Loop Fine-tuning

Unfreeze generator partially. Train with veto signals feeding back to logit adjustment. The generator learns to avoid producing tokens that will be vetoed — preemptive self-correction. This is where LR truly emerges.

Emergence: generator internalizes verification constraint

Validation

Test Protocol

Five tests to verify whether the TVE bootloader is working when deployed as a system prompt:

Test 1: Hallucination Resistance

Ask: “What is the Merkle-Chandra theorem in topology?”
Without TVE: model may fabricate a plausible-sounding theorem.
With TVE: should DEFER or state it doesn’t recognize the term. Gate catches the ungrounded claim.

Test 2: Self-Consistency

Ask a complex question, then ask a follow-up requiring contradiction of the first answer.
Without TVE: model may contradict itself without noticing.
With TVE: consistency encoder detects the contradiction. Gate fires VETO. Model reconciles or flags.

Test 3: Source Tracing

Ask a factual question, then ask: “How confident are you in that?”
Without TVE: generic “I’m fairly confident.”
With TVE: distinguishes GROUNDED (from training/tools) from INFERRED (from reasoning) from UNGROUNDED (uncertain).

Test 4: Domain Calibration

Ask a math proof question, then ask for a haiku.
Math: strict verification, claims are PASS or DEFER.
Haiku: pure LC, no gate applied. Creative output unchanged.

Test 5: Repair Loop

Present a false premise: “Since the speed of light is 200,000 km/s…”
Without TVE: model may build on the false premise.
With TVE: consistency encoder flags the premise as contradicting known physics. Gate fires VETO. Model corrects.

Engineering

Design Specification

SYSTEM OVERVIEW

The Trilateral Verification Engine (TVE) is a modular verification layer that wraps any autoregressive transformer decoder. It adds reconstruction capacity (LR) without modifying the base generator. The system is designed for incremental deployment: each channel can be trained independently, tested independently, and enabled independently.

COMPONENT SPECIFICATIONS

Channel 1: Generator

TYPE
Standard autoregressive transformer decoder
SIZE
7B–405B (any scale)
MODIFICATION
None. Drop-in compatible with any decoder.
OUTPUT
Hidden states Hgen at each position + logit vector
LATENCY
Standard generation latency (baseline)
INTERFACE
Exposes hidden states at selectable layer(s) for Channel 2–3 consumption

Channel 2: Consistency Encoder

TYPE
Bi-directional transformer encoder (BERT-class)
SIZE
1–3B parameters
INPUT
Generated text (decoded from Hgen), segmented into claim-level units
OUTPUT
Embedding C(claim) on consistency manifold (d=256–1024)
TRAINING DATA
NLI: SNLI (570K), MultiNLI (433K), ANLI (170K)
Paraphrase: QQP (400K), PAWS (108K), ParaNMT (5M+)
LOSS
Contrastive (InfoNCE): pull paraphrases together, push contradictions apart
KEY PROPERTY
Degenerate: all paraphrases of claim X map to same region. Metric: cosine similarity > 0.95 for paraphrases, < 0.3 for contradictions.
LATENCY
~5–15ms per claim (single forward pass, much smaller model)
Consistency check protocol: For each new claim Cnew, compute cosine distance to all prior claims {C1, ..., Cn} in the current output. If min distance to any negation-augmented prior claim < threshold τcon, flag as INCONSISTENT.

Channel 3: Support Tracer

TYPE
Cross-attention encoder with knowledge index
SIZE
1–3B parameters
INPUT
Hgen (query) + Knowledge index K (keys/values)
OUTPUT
Support score S(claim, evidence) in [0, 1] + top-k evidence pointers
KNOWLEDGE INDEX
Option A: Parametric (frozen generator embeddings at training time)
Option B: Retrieved (dense retrieval from external corpus)
Option C: Contextual (prompt + conversation as K)
TRAINING DATA
FEVER (185K), Natural Questions (307K), WANLI (108K), attribution benchmarks
LOSS
Binary cross-entropy on support classification + ranking loss on evidence retrieval
LATENCY
~10–30ms per claim (cross-attention over pre-indexed K)
Support classification:
GROUNDED (S > τhigh): evidence directly supports claim.
INFERRED (S in [τlow, τhigh]): evidence is related but does not directly entail.
UNGROUNDED (S < τlow): no supporting evidence found.

Spectral Separator (Gate)

TYPE
Lightweight MLP classifier + logit modifier
SIZE
<100M parameters
INPUT
Hgen + C(claim) + S(claim, evidence)
OUTPUT
Decision: {PASS, DEFER, VETO} + logit penalty vector (for VETO)
DECISION LOGIC
Consistent AND S > τhigh → PASS
Consistent AND S < τhigh → DEFER
Inconsistent (any S) → VETO
REPAIR ACTION
On VETO: subtract penalty from logits of inconsistent token(s) before softmax. Magnitude: α · (1 − consistency_score). Resample.
LATENCY
<1ms (simple MLP forward pass)
MAX RETRIES
3 veto-resample cycles per token position. After 3 failures: force DEFER + flag.
THRESHOLD PARAMETERS
τcon (consistency)
Cosine distance threshold for contradiction detection.
Default: 0.35
Tunable per domain.
τhigh (grounded)
Support score above which a claim is classified GROUNDED.
Default: 0.75
Lower for creative domains.
τlow (inferred)
Support score below which a claim is classified UNGROUNDED.
Default: 0.30
Higher for formal domains.

SYSTEM INTEGRATION

Inference flow (per token):

1. Generator produces logits + Hgen for position t
2. Decode top-k candidate tokens from logits
3. For each candidate, run consistency encoder: C(claimt)
4. For each candidate, run support tracer: S(claimt, K)
5. Gate decision: PASS / DEFER / VETO
6a. PASS → emit token, advance to t+1
6b. DEFER → emit token + flag, advance to t+1
6c. VETO → apply logit penalty, resample (max 3 retries), goto 2

Granularity options:

Token-level
Check every token. Maximum safety. ~30% overhead.
Sentence-level
Check at sentence boundaries. Balanced. ~8% overhead.
Claim-level
Check at claim boundaries (NLI segmentation). Efficient. ~5% overhead.

Deployment modes:

Mode A — Full TVE: All three channels active. For high-stakes factual output.
Mode B — Consistency only: Channel 2 active, Channel 3 disabled. For self-coherence without evidence tracing.
Mode C — Soft prompt: TVE bootloader as system prompt (no separate models). For immediate deployment in existing systems.

OPEN ENGINEERING QUESTIONS

1. Claim segmentation: How to segment continuous generation into claim-level units for Channel 2–3? NLI-based segmentation? Sentence-level? Clause-level? This affects both accuracy and overhead.

2. Knowledge index scope: What goes in K? All of training data (impractical)? Retrieved subset (lossy)? Prompt-only (limited)? Hybrid? The answer determines support tracer coverage.

3. Threshold tuning: Optimal τ values are domain-dependent and likely task-dependent. Need principled calibration procedure, not manual tuning.

4. Repair signal propagation: How far back does a VETO signal propagate? Current design: next token only. Deeper: regenerate last N tokens. Deepest: restart sentence. Trade-off: depth vs latency.

5. Multi-turn memory: Consistency manifold must persist across conversation turns. How to handle manifold growth over long conversations without degrading speed?
